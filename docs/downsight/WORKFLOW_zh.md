# DownSight 双端协作

## 边界

主流程来自公开 EgoSmplx `269ec28d10b779045136b907d1fe2f9ee2acf0f7`；其身体后端、Sapiens2、WiLoR 和模型权重仍是外部依赖。此仓库不是完整可直接部署的后端。旧实验快照在 `experiments/` 中标明状态，不能直接推断与默认流程等价。`configs/pipeline.head01.developer.json` 是原工作站示例，不保证另一台机器可用；相对路径及部署说明见原有 docs。

## 每轮交接

1. 开发机读取远端最新提交、上轮报告及用户本轮指令；记录代码和后端版本，避免覆盖其他人的变更。
2. 为唯一 run 目录创建 `brief.md`、`report.md`、`review.md` 和 `evidence/`；从 `runs/templates/` 取报告模板。执行时由流水线在输出目录 `provenance/<uuid>.json` 记录启动和结束状态；它在本地记录完整展开配置，可能包含敏感内容，公开之前必须脱敏。原有 `run_state.json` 保存输入、代码和配置指纹。
3. 报告写明任务、样本、配置摘要、指标、失败、限制及建议。只选择必要、允许共享的关键日志和图，并对大文件记录地址和 SHA-256。检查日志中个人信息、凭据和受限数据。
4. 经允许发布本轮报告及源码提交并推送。每次都核对远端 HEAD 与提交结果；发生冲突时停止自动推送并保留本地工作，不用强制推送。
5. 本地 agent 读取仓库的提交和具体 run 报告，给出基于证据的建议并指明 commit 和 run ID；用户决定下一步。

`*.log` 在默认 `.gitignore` 中被忽略；需要分享的精简日志请整理为 `runs/<id>/log.txt`，不要把整个原始输出目录加入 Git。真正运行环境和完整日志留在外部存储。不要将权重、模型数据、视频、密钥或本机绝对路径批量上传。

## Provenance 当前覆盖和限制

每次输出目录下 `provenance/` 保存完整展开配置、pipeline 与后端 Git patch（仓库存在时）、未跟踪文件内容哈希、源码和输入哈希、资源实际 SHA-256、后端契约核对、状态和时间。它可能包含本机路径、秘密或用户数据，**只能存于本地；推送时必须脱敏**。未跟踪文件只有内容哈希，没有自动备份其内容；后端不是 Git 仓库时不能生成 Git patch。失败在目录建立或锁定前时不生成 provenance。

资源摘要在每次预检中重新读取计算；这是因为现有文件系统的时间戳不能可靠区分同大小内容变化。续跑指纹包含资源实际摘要和后端契约，但未涵盖全部运行环境、后端未列出的其他源码和模型运行的所有依赖。

后端源码清单在预检时按 `integrity.py` 中声明的扩展名遍历并计算逐文件及整体 SHA-256；清单和排除策略进入 provenance 与续跑指纹。它排除生成输出、模型及数据资源和单独部署环境；`data/` 内数据 JSON/TXT/XML 也排除。目录符号链接记录目标摘要但不跟随，目标在范围外时内容不会覆盖。此清单不是完整运行环境或所有二进制依赖的证明；添加其他后端源码或扩展名时须扩充策略。
