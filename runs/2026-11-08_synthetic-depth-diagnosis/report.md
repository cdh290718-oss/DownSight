- 基线：`40e2eba6cd9582b0ce420ce0302410a5329e2c78`，开始时 GitHub main 与本地一致；工作区已有一份无关未跟踪文件，本轮未改动、未提交。实验执行时工作树增加本 run 的诊断脚本，原拟合代码和输入未修改。数据和模型摘要、cam3 GPU / cam4 CPU 差异见[上轮报告](../2026-11-08_synthetic-original/report.md)。
- 范围：同一合成姿态的 cam3 主诊断、cam4 辅助核对；25 个身体关节使用预测减真值的相机坐标误差，z 为向前光轴。骨盆对齐只减去骨盆平移。原始中间结果不重新生成；消融复用原观测和初始化，运行在 CPU。全部数值见 `evidence/diagnosis.json`、`evidence/controls.json` 和执行记录。
- 状态：完成诊断；没有声称完整分解 80 mm 的因果贡献。本轮 Oracle 有意使用真值，**仅为诊断**，不是可部署的预测，也没有替换原结果。

## 误差从何时出现

| cam3 阶段 | 身体 25 点绝对均值 mm | 骨盆绝对误差 mm | 骨盆 z 误差 mm | 骨盆真值 z / 预测 z mm |
|---|---:|---:|---:|---:|
| raw | 341.31 | 214.11 | -42.15 | 664.35 / 622.20 |
| rigid | 104.66 | 133.76 | +114.10 | 664.35 / 778.45 |
| body | 93.23 | 111.68 | +99.49 | 664.35 / 763.84 |
| guided / final | 77.77 | 87.70 | +81.13 | 664.35 / 745.48 |

cam4 的骨盆 z 误差依次为 -47.08、+102.23、+105.28、+100.09 mm；两幅只是同一姿态，不是独立样本。cam3 final 骨盆误差向量为 (+24.51, -22.56, +81.13) mm，身体 25 点各轴绝对误差均值分别为 22.54、38.38、55.03 mm。虽然深度误差占主导，不能把 77.77 mm 的三维关节平均值全部当成统一平移或单纯深度误差。

骨盆对齐会使每个关节误差向量减去骨盆误差向量，并不保证每点误差降低。cam3 final 左右腕绝对误差 27.14 / 14.77 mm，对齐后 68.10 / 76.51 mm；左右肘绝对 25.51 / 22.35 mm，对齐后 76.20 / 73.04 mm。预测腕肘与骨盆之间的相对结构仍存在误差，且腕肘相对精确不能证明身体整体准确。

## 检测、拟合与约束

检测点相对真值只在真值关节位于镜头前且入画时统计，未判断遮挡；Sapiens 标注点与 SMPL-X 内部关节的解剖定义也不一定一致。因此下表是“检测到真值关节”的差异，不能全部等同网络检测错误。拟合残差采用原多项式相机；真值由 Brown–Conrady 相机生成，两模型差见上轮报告。

| cam3 点 | 检测到真值 px | final 到检测 px | final 到真值 px |
|---|---:|---:|---:|
| 左 / 右髋 | 35.25 / 40.89 | 32.43 / 19.05 | 37.15 / 29.98 |
| 左 / 右肘 | 30.30 / 4.40 | 24.50 / 12.63 | 22.94 / 16.60 |
| 左 / 右腕 | 10.97 / 4.70 | 15.39 / 9.77 | 5.78 / 7.25 |
| 左 / 右膝 | 19.00 / 29.56 | 2.29 / 0.77 | 21.16 / 30.25 |

左右肩检测点都入选原刚体和身体点集合，但两个真实内部肩关节不入画，因此不能据此计算可靠的检测到真值肩关节像素误差。原刚体阶段没有 WiLoR 目标，但有 Sapiens 腕点；不应把这个样本的刚体变化归因于 WiLoR。

用相同刚体初始化、相同置信度和原约束，在身体姿态阶段把 10 个入画身体目标替换成真值二维坐标，鼻和双肩仍用原检测：身体 25 点绝对误差 93.23 → 85.82 mm、骨盆对齐误差 98.35 → 75.78 mm；骨盆 z 误差 +99.49 → +98.02 mm。左髋 final 对照此处应看 body 阶段：body 的真值重投影 47.09 → 14.44 px，右髋 36.04 → 3.11 px。检测/点定义差异影响姿态拟合，但这个固定初始化的局部 Oracle 不能证明检测对刚体深度没有影响，也不能把这些差值解释为可加的误差份额。左右腕在此对照中绝对误差分别为 24.68 → 18.46 mm 和 48.24 → 48.86 mm；后续 MANO 阶段未重新运行。

真值本身与全部顶点 z ≥ 0.02 m 的原硬限制冲突：cam3 有 1443 个顶点小于阈值，其中按最大蒙皮权重归类为头部 969、颈部 0、其他 474；非头颈最小 z 为 8.43 mm。cam4 分别为 1971、1214、0、757 和 4.38 mm。分类只是模型蒙皮权重的近似，并不等同精确解剖分割；只排除头颈也不能令此真值完全满足 2 cm 规则。

固定其他条件的局部消融显示：

- 原刚体拟合对近深度使用软惩罚。重跑原条件精确复现；将近深度惩罚完全取消，骨盆 z 误差 +114.10 → +114.13 mm、25 点绝对均值 104.66 → 104.67 mm。仅排除头颈的结果同样接近原值。对于这个起点与优化过程，此项不是刚体偏远的主要原因；不能推广到其他帧或其他起点。
- 原身体姿态阶段既有 3 cm 起效的深度势垒，也有 2 cm 可行性筛选。固定原刚体起点，全部顶点改为只检查非头颈顶点，身体参数和网格逐元素完全一致，骨盆 z 均 +99.49 mm。原结果最小 z 41.14 mm，因此该阶段最终结果远离阈值；这一对照说明该阶段单独修改规则没有改变结果。
- 后续 guided 阶段的最小 z 为 23.17 mm，接近 2 cm 约束；没有对该阶段及融合做单因素消融，故不能推断其深度规则贡献为零。头部参考、腕距、形状固定、姿态范围、Sapiens/WiLoR 目标等仍可能存在耦合；本实验未分别归因。

刚体重投影从 raw 的极大偏差下降，而深度从偏近变偏远；这说明优化在有限二维观测、固定初始身体形状和姿态、目标与先验共同作用下选择了该解，并不单独证明哪一项是决定因素。真值几何不可行与“本次深度偏差是该规则造成”是不同结论。

## 复现与证据

复用上轮 `outputs/synthetic_original_20261108`，以同一身体 Python 环境和模型执行 `run_ablation.py`、`oracle_detection.py`、`rigid_ablation.py`，再执行 `diagnose.py` 和 `collect_controls.py`（需把仓库加入 `PYTHONPATH`）。脚本明确限定四线程、CPU 和单视角，优化步数与上轮一致；未安装依赖、未修改后端。`evidence/*_execution.json` 为退出状态及用时；`controls.json` 保存完整采样轨迹、参数差、目标残差；`diagnosis.json` 包含每点误差、分类和输入文件哈希。原始 NPZ 与完整日志在仓库忽略的本地输出中。

诊断脚本首次未设置 PYTHONPATH，第二次错误查找右目缓存路径，均失败并保留脱敏记录，修正后退出 0，原拟合未改。原路径用 `<WORKSPACE>` 等占位符代替；本轮不发布权重、数据、NPZ、完整原始输出、完整 provenance 或 patch。各推送前工作区、暂存、提交与远端的核查见 `evidence/prepush.json`；不声称历史全量通过审计。
